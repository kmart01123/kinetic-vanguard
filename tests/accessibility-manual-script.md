# Accessibility manual script

This script is evidence guidance. A completed report must identify the exact release-verification workflow run, approved SHA, candidate artifact name, and GitHub artifact digest.

| ID | Profile | Action | Expected result | Pass criteria |
|---|---|---|---|---|
| HOME-001 | both | Load the publication without a fragment and review it by keyboard and heading navigation. | Start Here is the level-two page heading; its sections are level three; Discipline card titles are level four; Browse rules and Find by name are absent from the focus order; initial focus remains unchanged. | Heading order is complete, the skip link reaches the shared main content, and no hidden reference control receives focus. |
| VIEW-001 | both | Move between Start Here and Rules Reference with the persistent navigation, then use Back and Forward. | The current view is identified, each user-initiated switch moves focus to the opened view heading, and history restores the prior view and complete reference state without a restoration focus jump. | View, canonical category ID, topic, entity, Name selection, Calculator state, and valid focus origin restore exactly; no classification or result state exists. |
| DEST-001 | both | Activate each Discipline card and representative checklist, glossary, and next-destination links. | Each control exposes a copyable canonical fragment, opens the intended existing rule, reveals Topic and Name controls, and focuses the opened rule heading. | Destination, accessible name, history entry, and focus behavior match canonical navigation data. |
| PRINT-001 | both | Print Start Here, then print the Subclass Feature Reference. | Persistent and primary interactive navigation is hidden from Start Here print output; onboarding remains readable; reference printing still includes every feature-reference row and column. | Neither print view has page-level horizontal overflow or clipped authoritative text. |
| NAME-001 | both | Load the publication and reach Name by keyboard. | Placeholder is “Select a rule by name”; the native select has the accessible label “Name” and a visible focus indicator; no Open button is present. | Label, placeholder, focus, and control type match. |
| NAME-002 | both | Open the Name menu and navigate choices without committing one. | No navigation, focus move, URL change, history write, or announcement occurs before the native selection is committed. | State remains unchanged while the menu is only open or being traversed. |
| NAME-003 | both | Commit representative deck-owned and shared/system Name selections with mouse, touch, and keyboard interaction. | One history entry is pushed; deck-owned names open their Calculator card, shared/system names open their canonical Rules Reference topic, and Name stays synchronized for reference destinations. | Exactly one canonical update occurs with no duplicate title announcement. |
| HIST-001 | both | Use Back and Forward after TOPIC-001 and NAME-003. | Back restores the prior Topic and Name state; Forward restores the exact destination and selected Name. | Exact route and remaining history state restore without transient selection activation or classification fields. |
| ROUTE-001 | both | Load a valid entity fragment. | Entity topic loads and Name synchronizes to the entity. | One or fewer consolidated notices; no unexpected focus move. |
| TOPIC-001 | both | Change the Topic selector with keyboard and touch, including at a mobile viewport. | All eleven authority-derived shared/core topics remain reachable and the selected topic is announced. | The canonical category/topic fragment, visible topic content, focus, and Back/Forward behavior agree. |
| LEGACY-001 | both | Load a valid reference fragment containing a legacy `filters=` parameter, then a legacy individual-feature fragment with `filters=`. | The obsolete parameter is removed with `replaceState`; reference content stays reachable, and the individual feature canonicalizes to its Calculator card. | No filter controls or filter state appear in the DOM, focus order, history state, or resulting URL. |
| STATUS-P | prototype | Inspect the artifact status. | Prototype banner is visible and exposed to accessibility APIs. | Banner is unmistakable after copying the file. |
| STATUS-R | release | Inspect the artifact status. | Prototype banner is absent. | Release metadata reports release. |
